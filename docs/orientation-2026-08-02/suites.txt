NOTE `available()` reads the env var and then actually opens a connection — it is not a string check. `scratch_url()` returns `os.environ.get("JOBS_SCRATCH_DATABASE_URL") or os.environ.get("DATABASE_URL")`; `available()` returns False on empty, else `psycopg.connect(url, connect_timeout=5)` + `SELECT 1` inside a bare `except Exception: return False`. So an unreachable Postgres skips just as an unset var does — and the broad except means a genuine driver/auth bug also silently reads as 'skip', which matches this repo's stated 'silence is the failure mode' hazard.
